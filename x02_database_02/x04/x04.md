# 서브쿼리

## 서브쿼리 소개

### 문제
- 우리 쇼핑몰에서 판매하는 상품들의 평균 가격보다 비싼 상품은 무엇이 있을까?

### 논리적인 해결 순서
- 쿼리 1: 판매하는 상품들의 평균 가격을 구한다
- 쿼리 2: 구한 평균을 가지고 비싼 상품을 구한다
- 문제
    - 번거로움
    - 오류에 취약함: 중간에 상품 가격이 바뀐다면 잘못된 기준으로 데이터를 조회 할 수 있음

### 서브 쿼리의 개념
- 하나의 SQL 쿼리 문 안에 또 다른 select 쿼리를 의미함
- 괄호 안에 있는 서브 쿼리가 먼저 실행됨
- 서브 쿼리의 결과를 바깥쪽 메인 쿼리에게 전달하여, 메인 쿼리가 그 결과를 사용해서 최종 작업을 수행함

### 서브 쿼리로 해결
```sql
select name, price
from products
where price > (select avg(price) from products);
```
- 순서
    - 데이터베이스는 괄호 안의 서브쿼리를 먼저 실행
    - 반환 결과는 단일 값을 가짐
    - 최종적으로 이 변환된 메인 쿼리가 실행되어 결과를 보여줌

### 서브 쿼리 종류와 특징
- where 절 외에도 쿼리의 다양한 위치에서 각기 다른 역할을 수행함
- 서브 쿼리는 반환하는 행과 컬럼의 수에 따라 종류가 나위며, 사용되는 위치와 연산자에 따라 그 역할이 결정됨

## 스칼라 서브쿼리

### 단일 컬럼 / 단일 행
- 결과가 오직 하나의 행, 하나의 컬럼으로 나오는 경우를 말함(스칼라 = `단 하나의 값`)

### 사용할 수 있는 연산자
- =, > , <, >=, <=, <>

### 문제
- 특정 주문(order_id = 1)을 한 고객과 같은 도시에 사는 모든 고객을 찾고 싶다

### 해결
```sql
select u.address
from orders o
inner join users u on o.user_id = u.user_id
where o.order_id = 1;

select *
from users u
where u.address = '주소';
```

```sql
select *
from users
where address = (select u.address
        from orders o
        inner join users u on o.user_id = u.user_id
        where o.order_id = 1
    );
```

### 스칼라 서브쿼리의 치명적 오류
- 반드시, 무슨 일이 있어도 단 하나의 행만 반환해야함

## 단일 컬럼, 다중 행 서브쿼리

### 문제
- 전자기기 카테고리에 속한 모든 상품들을 주문한 주문 내역을 전부 보고 싶다
- 순서
    - 전자기기 카테고리에 속한 상품들의 id를 모두 찾는다
    - 그 다음, orders 테이블에서 product_id가 우리가 찾아낸 id 목록 안에 포함된 주문들을 모두 찾는다

### IN 연산자: 목록에 포함된 값과 일치하는지 확인
- 특정 컬럼의 값이 괄호 안의 목록 중 하나라도 일치하면 참을 반환함
```sql
select *
from orders o
where o.product_id in (
    select p.product_id 
    from products p 
    where p.category = '전자기기'
    );
```

### ANY, ALL 연산자: 목록의 일부/모든 값과 비교
- `> ANY (서브쿼리)`: 서브쿼리가 반환한 여러 결과값 중 어느 하나보다만 크면 참
- `> ALL (서브쿼리)`: 서브쿼리가 반환한 여러 결과값 모두보다 커야만 참
- `< ANY (서브쿼리)`: 최대값보다 작으면 참
- `< ALL (서브쿼리)`: 최소값보다 작으면 참
- `= ANY (서브쿼리)`: IN 과 완전히 동일한 의미

### 실제 쇼핑몰 데이터로 ANY, ALL 사용해보기
- 문제 1: 전자기기 카테고리의 최솟값보다 비싼
```sql
select *
from products p1
where p1.price > ANY(
    select p2.price
    from products p2
    where p2.category = '전자기기'
);
```

- 문제 2: 전자기기 카테고리의 모든 상품보다 비싼 상품 찾기
```sql
select *
from products p1
where p1.price > ALL(
    select p2.price
    from products p2
    where p2.category = '전자기기'
);
```

## 다중 컬럼 서브쿼리

### 개념
- 서브쿼리의 select 절에 두 개 이상의 컬럼이 포함된 경우를 말함
- 메인쿼리의 where 절에서 여러 컬럼을 동시에 비교해야 할 때 매우 유용함

### 문제
- 우리 쇼핑몰의 고객 네이트(user_id = 2)가 한 주문(order_id = 3)이 있음
- 이 주문과 동일한 고객이면서 주문 처리 상태가(status)도 같은 모든 주문을 찾아보자 

### 다중 컬럼 서브쿼리로 문제 해결하기
```sql
select user_id, status from orders where order_id = 3;

select *
from orders
where (user_id, status) = (select user_id, status from orders where order_id = 3);
```

### 주의할 점
- 다중 컬럼 서브쿼리를 = 연산자와 함께 사용할 때
- 단일 행 서브쿼리와 마찬가지로 서브쿼리의 결과가 반드시 **하나의 행**

### 다중 컬럼 서브쿼리와 IN 연산자
- 각 고객별로 가장 먼저 한 주문의 주문 ID, 사용자 ID, 사용자 이름, 제품 이름, 주문 날짜를 조회
```sql
select
    o.order_id,
    u.user_id,
    u.name,
    p.name,
    o.order_date
from orders o
inner join users u on o.user_id = u.user_id
inner join products p on o.product_id = p.product_id
where (u.user_id, o.order_date) in ( -- 각 고객별 최초 주문
    select user_id, min(order_date)
    from orders
    group by user_id
);
```

## 상관 서브쿼리 1

### 문제
- **각 상품별로, 자신이 속한 카테코리의 평균 가격 이상의 상품들을 찾아라**
- 핵심
    - 전체 평균 가격이 아닌 자신이 속한 바로 그 카테고리의 평균 가격과 비교해야 함

### 해결
- 서브쿼리가 메인쿼리에서 현재 처리 주인 행의 특정 값을 알아야만 계산을 수행할 수 있을 때, 바로 상관 서브 쿼리를 사용해야 함
- 상관: 메인쿼리와 서브쿼리가 서로 영향을 준다는 뜻

### 왜 상관 서브쿼리가 필요한가
- 위 문제를 해결하려면, products 테이블의 각 행을 하나씩 확인하면서 비교 대상을 동적으로 바꿔야함

### 상관 서브쿼리의 개념
- 메인쿼리와 서브쿼리가 서로 연관관계를 맺고 동작하는 서브쿼리
- 서브쿼리가 독립적으로 실행될 수 없고, 메인쿼리 값을 참조하여 실행되는 것이 특징

### 비상관 서브쿼리 vs 상관 서브쿼리
- 비상관 서브쿼리: 서브쿼리가 단 한 번 실행된 후, 그 결과를 메인쿼리가 사용함
- 상관 서브쿼리:
    - 메인쿼리가 먼저 한 행을 읽음
    - 읽혀진 행의 값을 서브쿼리에 전달하여, 서브쿼리가 실행됨
    - 서브쿼리 결과를 이용해 메인쿼리의 where 조건을 판단함
    - 메인쿼리의 다음 행을 읽고, 2-3번 과정을 반복함

- 즉, 서브쿼리가 메인쿼리의 행 수만큼 반복 실행될 수 있음

### 상관 서브쿼리로 문제 해결하기
```sql
select *
from products p1
where 
	p1.price >= (
		select avg(p2.price) 
		from products p2 
		where p2.category = p1.category
	);
```
- O(N^2): 서브쿼리 안에서도 테이블을 훑음

## 상관 서브쿼리 2

### 한 번이라도 주문된 상품 조회하기
- 지금까지 한 번이라도 주문된 적이 있는 상품

### 비상관 서브쿼리로 해결하기
```sql
select *
from products p
where p.product_id not in (
    select distinct product_id
    from orders
);
```
- 최선이 아닐 수도 있음

### EXISTS를 사용한 더 효율적인 방법
- in 방식은 orders 테이블이 매우 클 경우, 성능 문제를 일으킬 수 있음
- `exists`는 서브쿼리가 반환하는 결과값 자체에는 관심이 없고, 오직 서브쿼리의 결과로 행이 하나라도 존재하는지 여부만 체크함

### EXISTS 연산
- 서브쿼리 결과 행이 1개 이상이면 TRUE
- 서브쿼리 결과 행이 0개이면 FALSE
```sql
select
    product_id,
    name,
    price
from
    products p
where exists (
    select 1
    from orders o
    where o.product_id = p.product_id
);
```
- o.product_id = p.product_id를 만족하는 행이 있는 순간 true를 반환하고 즉시 탐색 중단
- 없으면 false를 반환

### not in과 null
- not in을 사용할 때 null이 있는 순간 unknown을 반환하기 때문에 0건으로 나오게 됨

### 상관 서브쿼리와 성능
- 성능에 매우 주의해야함
- 메인쿼리의 행 수만큼 서브쿼리가 반복 실행될 수 있음
- 메인쿼리가 다루는 데이터의 양이 많아지면 쿼리 전체 성능이 급격히 저하될 수 있음

- 많은 경우, 상관 서브쿼리는 join으로 동일한 결과를 얻도록 재작성할 수 있음
- 데이터베이스 옵티마이저가 join을 더 효율적으로 처리하는 경우가 많음
    - 내부적으로 상관 서브쿼리를 join으로 처리하는 경우도 있음

- **join으로 표현하기 너무 복잡하거나 exists를 통해 더 효율적인 실행이 가능할 때 적절히 사용하는 것이 효율적임**

## select 서브쿼리

### select절로 서브쿼리를 가져온다면?
- 필터가 아닌, 그 자체가 하나의 컬럼처럼 동작하게 됨
- 참고로 반드시 스칼라 서브쿼리를 사용해야함

### 비상관 서브쿼리
- 문제: 모든 상품 목록을 조회하는데, 각 상품의 가격과 함께 전체 상품의 평균 가격을 모든 행에 함께 표시해서 개별 상품 가격이 평균과 얼마나 차이 나는지 비교해보고 싶다

```sql
select name, price, (select avg(price) from products)
from products;
```

- 실행 흐름
    - 서브쿼리를 딱 한 번 실행하고, 스칼라 서브쿼리를 단 한 번 먼저 실행함
    - 데이터베이스는 이 값을 기억하고 재사용함

### 상관 서브쿼리
- 문제: 전체 상품 목록을 조회하면서, 각 상품별로 총 몇 번의 주문이 있었는지 총 주문 횟수를 함께 보고 싶음

```sql
select 
    name,
    price,
    (select count(*) from orders o where o.product_id = p.product_id)
from products p;
```

### 실무 팁: 성능에 주의하라
- join으로 표현하기 복잡한 로직을 직관적으로 표현할 수 있게 해주지만, 강력한 만큼 주의해서 사용해야함
- 가장 큰 단점은 **성능 저하**

- 조인으로 해결하기
```sql
select
    p.product_id,
    p.name,
    p.price,
    count(o.order_id)
from products p
    left join orders o on p.product_id = o.product_id
group by p.product_id, p.name, p.price;
```

## 테이블 서브쿼리(인라인 뷰)

### 개념
- 하나의 독립된 가상 테이블처럼 사용되기 때문에 테이블 서브쿼리라고 함
- 인라인 뷰라고도 함

### 문제
- 각 상품 카테고리별로, 가장 비싼 상품의 이름과 가격을 조회하고 싶음
```sql
select category, max(price)
from products
group by category;
```
    - 상품명을 구할 수 없음
    - group by category, name도 할 수 없음

### 해결 - 비상관 서브쿼리
```sql
select 
	p.product_id,
	p.name,
	p.price
from products p 
	inner join (
		select category, max(price) as max_price
		from products
		group by category
	) cmp
	on p.category = cmp.category and p.price = cmp.max_price;
```
- 서브쿼리로 테이블을 만들어서 메인 테이블이랑 join을 진행
- 즉 하나의 테이블로 보는 것 => 인라인 뷰, 테이블 서브쿼리
- 이때 가격을 비교하도록해서 문제를 해결할 수 있음

## 서브쿼리 vs JOIN

### 문제
- 서울에 거주하는 모든 고객들의 주문 목록을 조회해라

### 해결 방법 1: 서브쿼리 사용
```sql
select
    *
from orders o
where o.user_id in (select u.user_id from users u where u.address like '서울%');
```
- 읽기가 매우 쉬움
    - 서울에 거주하는 모든 고객들을 찾고
    - 해당 user_id를 가지는 모든 orders 테이블의 행을 조회

### 해결 방법 2: JOIN 사용
```sql
select 
    *
from orders o
inner join users u
    on o.user_id = u.user_id
where u.address like '서울%';
```
- 읽기는 어려움
    - 주문과 사용자 테이블을 조인하고
    - 고객 주소가 서울인 고객들만 걸음

### 성능
- join이 서브쿼리보다 성능이 더 좋거나 최소한 동일한 경우가 많음

- 이유
    - 옵티마이저에게 더 많은 정보를 제공함
    - 인덱스를 어떻게 활용하고 어떤 테이블을 먼저 읽을지 가장 효율적인 실행 계획을 선택할 수 있음

- 하지만
    - 요즘 데이터베이스는 똑똑해져서
    - 서브쿼리를 내부적으로 join 구문으로 자동 변환해서 실행함
    - **쿼리 실행 계획**을 확인하는 것이 좋음

### 가독성
- 서브쿼리
    - 쿼리의 논리적인 단계를 명확하게 구분해주어, 복잡한 로직을 더 이애하기 쉽게 만들어주는 경우가 많음

- JOIN
    - 쿼리에 필요한 모든 데이터 소스를 한 눈에 보여주고, 여러 테이블의 컬럼을 조회해야할 때는 구조적으로 더 깔끔함

### 최종 결론
- JOIN을 우선적으로 고려
    - JOIN으로 표현하기 너무 복잡하거나, 서브쿼리의 가독성이 훨씬 좋다면 서브쿼리
    - EXISTS를 활용

- **성능이 의심될 때는 반드시 측정**
    - `EXPLAIN`과 같은 도구를 사용해서 데이터베이스가 어떻게 쿼리를 실행하는지 계획을 분석하고, 실제 실행 시간을 측정하여 더 나은 방법을 선택해야함
