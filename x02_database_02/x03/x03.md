# 조인 2 - 외부 조인과 기타 조인

## 외부 조인 1

### 문제
- 가입은 했지만 아직까지 주문을 한 번도 하지 않은 고객 정보
- 내부 조인으로 이 문제를 해결할 수 없음
- **외부 조인으로 이 문제를 해결할 수 있음**

### 외부 조인의 필요성
- 내부 조인으로는 주문 기록이 없는 고객을 찾을 수 없음
- 외부 조인을 사용하면
    - 한 쪽 테이블에만 있는 데이터도 결과에 포함시킬 수 있음

### 외부 조인의 필요성 및 개념
- 조인은 본질적으로 두 테이블의 집합에 대한 이야기
- 필요성
    - 외부 조인은 두 테이블을 조인할 때, 특정 테이블의 데이터는 on 조건과 맞지 않더라도 모두 결과에 포함시키는 방법
    - 기준이 되는 테이블
        - left outer join: 왼쪽 테이블을 포함
        - right outer join: 오른쪽 테이블 포함
        - full outer join: 양쪽 모두를 포함(MySQL에서 지원 X)

### left outer join vs right outer join
- **기준이 중요함**
> 참고: outer도 생략 가능 / left/right는 반드시

- left join
    - from절 테이블이 기준이 됨
    - 왼쪽 테이블의 모든 데이터를 결과에 포함
    - 그 다음, on 조건에 맞는 데이터를 오른쪽 테이블에서 찾아 옆에 붙여줌
    - **만약 오른쪽 테이블에 짝이 맞는 데이터가 없다면, 그 자리는 `null`값으로 채워짐**

- right join
    - left 조인에서 오른쪽(join 절에 있는 테이블)이 기준이 된다

### 실습 1: left join으로 한 번도 주문하지 않은 고객 찾기
```sql
select
    u.user_id,
    u.name,
    o.user_id,
    o.order_id
from users u
    left join orders o on u.user_id = o.user_id
order by
    u.user_id;
```

```sql
select 
    u.user_id,
    u.name,
    o.user_id,
    o.order_id
from users u
    left join orders o on u.user_id = o.user_id
where
    o.user_id is null
order by
    u.user_id;
```

```sql
select 
    u.user_id,
    u.name,
    u.email
from users u
    left join orders o on u.user_id = o.user_id
where
    o.user_id is null
order by
    u.user_id;
```
- 한 번도 주문하지 않은 고객을 찾음!!

## 외부 조인 2

### 실습 2: left join으로 단 한 번도 팔리지 않은 상품 찾기
```sql
select
    p.product_id,
    p.name
    p.price
from products p
    left join orders o on p.product_id = o.product_id
where o.product_id is null;
```

### 실습 3: 실습 2를 right outer join을 사용
```sql
select
    p.product_id,
    p.name,
    p.price
from orders o
    right join products p on o.product_id = p.product_id
where o.product_id is null;
```

### left / right join 선택
- 서로 위치를 바꾸어 쓸 수 있음(실습 2, 실습 3)
- 기준을 정하면 어차피 결과는 같음을 알 수 있음
    - right는 사실상 필요 없음 => 그냥 기준을 바꿔버리면 결과가 동일함

- 실무:
    - left join을 훨씬 많이 사용함
    - 기준이 되는 테이블을 from에 적는 것이 직관적임

## 조인의 특징

### 조인에서 데이터가 늘어나는 경우
- 기준으로 삼는 테이블의 한 행이 다른 쪽 테이블의 여러 행과 연결될 수 있다면 전체 행 수는 늘어남
- 반대로 한 행이 다른 쪽 테이블의 단 하나의 행과 연결되거나, 아무 행과도 연결되지 않는다면 행의 수는 늘어나지 않음

### 기본 키와 외래 키의 관계
- 기본키: 테이블에서 각 행을 고유하게 식별하는 값
    - user_id, product_id, order_id
    - 테이블 내에서 절대 중복될 수 없는 값

- 외래키: 다른 테이블의 기본키를 참조하는 값
    - orders의 user_id, product_id

- 부모 - 자식 관계
    - 부모: PK를 가지고 있는 테이블 (users, products) 
    - 자식: FK를 통해 부모 테이블을 참조하는 테이블(orders)

### 행 개수 늘어나는지 안늘어나는지 정리
- **자식 -> 부모: 행 개수가 늘어나지 않음**
- 부모 -> 자식: 행 개수가 늘어날 수 있음

### 특정 고객 '션'으로 조인 원리 파헤치기
```sql
select
	user_id, name, email
from 
	users
where
	user_id = 1;

select
	order_id, product_id, user_id
from
	orders
where 
	user_id = 1;
```

### 경우 1: 자식 -> 부모(orders -> users)
```sql
select *
from orders o
    inner join users u on o.user_id = u.user_id 
where o.user_id = 1;
```
- 자식: 행 두 개
- 결과: 행 두 개
    - 유지됨

### 경우 2: 부모 -> 자식(users -> orders)
```sql
select *
from users u
    inner join orders o on u.user_id = o.user_id
where u.user_id = 1;
```
- 부모: 행 한 개
- 결과: 행 두 개
    - 유지 안됨

### 정리: 언제 행이 늘어나고 언제 그대로인가?
- 행 개수 유지: 자식에서 부모로 조인할 때(Many to One)
    - FK -> PK 조인
    - 원리: 자식 테이블의 모든 행은 부모 테이블의 단 하나의 행과 매칭됨
    - 결과: 기준이 되는 자식 테이블의 행 개수가 그대로 유지됨

- 행 개수 증가: 부모에서 자식으로 조인할 때(to Many)
    - PK -> FK 조인
    - 원리: 부모 테이블의 한 행은 자식 테이블의 여러 행과 매칭될 수 있음
    - 결과: 전체 행의 수가 기준 테이블보다 늘어날 수 있음

### 왜 중요할까?
- 데이터를 잘못 분석할게 될 위험이 있음
    - from users join orders를 한 후 고객 수를 세기 위해서 count(u.user_id)를 한 상황
    - 행의 갯수가 늘어났기 때문에 고객의 수가 나오는 것이 아니라 주문한 고객 수가 나오게 됨(사실상 전체 주문 수가 나옴)
    - 집계 함수를 올바르게 사용할 수 있음

### 참고: 조인의 유연성
- PK-FK 관계에서만 사용할 수 있는 것이 아님
- **조인의 핵심은 두 테이블의 특정 열의 값이 같은가?**
    - **실제로는 어떤 열이든 조인 조건으로 쓸 수 있음**
    - **단, 데이터 타입만 같다면!!**

### 동명이인 찾기 (이름으로 조인)
```sql
select A.이름, A.연락처, B.부서
from 고객 as A
    joni 직원 as B on A.이름 = B.이름; 
```

## 셀프 조인

### 문제
- 나의 상사 찾기

### self join 개념과 원리
- 새로운 종류의 join 명령어가 아님
- 하나의 테이블을 자기 자식과 조인하는 기법을 말하는 것

- 원리의 핵심
    - **테이블 별칭**
    - employees e: 모든 직원의 목록
    - employees m: 모든 상사의 목록

### 예제
```sql
select
	e.name,
	m.name
from employees e
left join employees m
	on e.manager_id  = m.employee_id;
```
- 상사가 없는 경우를 위해서 left outer join으로 실행

## CROSS 조인

### 문제
- 짝이나 관계가 없는 두 집단을 가지고 가능한 모든 조합을 만들어내야 한다면?

### cross join의 개념과 카테시안 곱
- cross join
    - 조인 조건 없이 한쪽 테이블의 모든 행을 다른 쪽 테이블의 모든 행과 하나씩 전부 연결하는 단순한 조인 방식
    - 연결고리가 없기 때문에 `on`절을 사용하지 않음

- 카테시안 곱
    - N개의 행을 가진 테이블 x M개의 해을 가진 테이블
    - N x M의 행을 가진 테이블이 출력됨

### 실습: 상품 옵션 조합 만들기
```sql
select
	*
from colors c
	cross join sizes s; 
```

```sql
select
	concat('기본 티셔츠-', c.color, '-', s.size) as product_name,
	s.size,
	c.color
from sizes s
cross join colors c;
```

### insert into ... select로 상품 옵션 마스터 테이블 만들기
```sql
CREATE TABLE product_options (
 option_id BIGINT AUTO_INCREMENT,
 product_name VARCHAR(255) NOT NULL,
 size VARCHAR(10) NOT NULL,
 color VARCHAR(20) NOT NULL,
 PRIMARY KEY (option_id)
);
```

```sql
INSERT INTO product_options (product_name, size, color)
SELECT
 CONCAT('기본티셔츠-', c.color, '-', s.size) AS product_name,
 s.size,
 c.color
FROM
 sizes AS s
CROSS JOIN
 colors AS c;
```

### 실무에서의 치명적인 주의사항
- 가장 위험한 조인
- 결과 행 수가 기하급수적으로 늘어날 수 있기 때문
- 100만 * 10만 = 1000억 건 => 데이터베이스 서버가 다운될 수 있음

## 조인 종합 실습

### 조인 종합
- inner join
- outer join
    - left outer join
    - right outer join
    - full outer join
- self join
- cross join

### 문제
- 2025년 6월에 서울에 거주하는 고객이 주문한 모든 내역에 대해서
    - 고객 이름
    - 고객 이메일
    - 주문 날짜
    - 주문한 상품
    - 상품 가격
    - 주문 수량
- 을 포함하는 최신 주문 순으로 작성

### 문제 분석 및 해결 전략
- 필요한 정보는 무엇인가
    - 고객 이름, 고객 이메일
    - 주문 날짜, 주문 수량
    - 주문한 상품명, 상품 가격
    - 주문 내역에 대한 것이므로 주문 테이블을 기준으로 시작


### 쿼리
```sql
select
	u.name,
	u.email,
	o.order_date,
	p.name,
	p.price,
	o.quantity
from 
	orders o
	inner join users u on o.user_id = u.user_id
	inner join products p on o.product_id = p.product_id
where 
	u.address like '서울시%'
order by
	o.order_date desc;
```
