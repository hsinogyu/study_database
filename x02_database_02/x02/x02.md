## 실습 데이터 준비

### DDL
```sql
-- 데이터베이스가 존재하지 않으면 생성
CREATE DATABASE IF NOT EXISTS my_shop2;
USE my_shop2;
-- 테이블이 존재하면 삭제 (실습을 위해 초기화)
DROP TABLE IF EXISTS orders;
DROP TABLE IF EXISTS users;
DROP TABLE IF EXISTS products;
DROP TABLE IF EXISTS employees;
DROP TABLE IF EXISTS sizes;
DROP TABLE IF EXISTS colors;
-- 고객 테이블 생성
CREATE TABLE users (
 user_id BIGINT AUTO_INCREMENT,
 name VARCHAR(255) NOT NULL,
 email VARCHAR(255) NOT NULL UNIQUE,
 address VARCHAR(255),
 birth_date DATE,
 created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
 PRIMARY KEY (user_id)
);
-- 상품 테이블 생성
CREATE TABLE products (
 product_id BIGINT AUTO_INCREMENT,
 name VARCHAR(255) NOT NULL,
 category VARCHAR(100),
 price INT NOT NULL,
 stock_quantity INT NOT NULL,
 PRIMARY KEY (product_id)
);

-- 주문 테이블 생성
CREATE TABLE orders (
 order_id BIGINT AUTO_INCREMENT,
 user_id BIGINT NOT NULL,
 product_id BIGINT NOT NULL,
 order_date DATETIME DEFAULT CURRENT_TIMESTAMP,
 quantity INT NOT NULL,
 status VARCHAR(50) DEFAULT 'PENDING',
 PRIMARY KEY (order_id),
 CONSTRAINT fk_orders_users FOREIGN KEY (user_id)
 REFERENCES users(user_id),
 CONSTRAINT fk_orders_products FOREIGN KEY (product_id)
 REFERENCES products(product_id)
);
-- 직원 테이블 생성 (SELF JOIN 실습용)
CREATE TABLE employees (
 employee_id BIGINT AUTO_INCREMENT,
 name VARCHAR(255) NOT NULL,
 manager_id BIGINT,
 PRIMARY KEY (employee_id),
 FOREIGN KEY (manager_id) REFERENCES employees(employee_id)
);
-- 사이즈 테이블 (CROSS JOIN 실습용)
CREATE TABLE sizes (
 size VARCHAR(10) PRIMARY KEY
);
-- 색상 테이블 (CROSS JOIN 실습용)
CREATE TABLE colors (
 color VARCHAR(20) PRIMARY KEY
);
```

## 조인이 필요한 이유

### 상황
- 최근 주문 현황을 고객 이름과 상품명을 포함해서 보고서로 만들어줘

### 문제
- orders 테이블에는 고객 이름과 상품명이 없음
- orders 테이블만 보고서는 user_id가 1인 고객이 누구인지, product_id가 4인 상품이 무엇인지 즉시 알 수 없음

### 해결 방안 1
- 고객 이름을 구하기 위해서는 users 테이블을 통해 user_id에 해당하는 고객명을 직접 조회
- 상품명을 구하기 위해서는 products 테이블을 통해 product_id에 해당하는 상품명을 직접 조회

> 사실상 이렇게 하면 안됨

### 해결 방안 2
- 처음부터 큰 테이블 하나에 다 저장하면 안되나?
- 문제
    - 데이터 중복
    - 갱신 이상
    - 삽입 이상
    - 삭제 이상

- 해결
    - 정규화: 때문에 현재 테이블이 분리되어있는 것

### 해결 방안 3

## 내부 조인 1

### 내부 조인의 개념(Inner Join)
- 두 테이블을 연결할 때, **양쪽 테이블에 모두 공통으로 존재하는 데이터만을 결과로 보여줌**
- 기준이 되는 컬럼의 값이 서로 일치하는 행들만 짝을 지어주는 것

### 문법 
```sql
select 컬럼1, 컬럼2, ...
from 테이블A 
inner join 테이블B
    on 테이블A.연결컬럼 = 테이블B.연결컬럼
```
- orders 테이블에 user_id가 1인 주문이 있고, users 테이블에 user_id가 1인 회원이 있다면 둘은 함게 결과에 포함됨
- orders 테이블에 user_id가 99인 주문이 있지만 users 테이블에 user_id가 99인 회원이 없다면, 결과에서 제외됨(실제로는 데이터 무결성을 위해 외래키 제약조건을 사용하므로 이런 경우는 발생하지 않음)

- 참고
    - 내부 조인에서 inner는 생략할 수 있음 => join이라고 쓰면 inner join으로 동작함

### 실습: 주문별 고객 정보 조회하기
```sql
select *
from orders o
inner join users u 
	on o.user_id = u.user_id
```

### 조인 과정
- 데이터베이스는 orders / users 테이블을 조회
- join on에 의해 orders의 user_id와 users의 user_id를 기준으로 조인함
- orders의 user_id의 값으로 users의 user_id 항목을 찾고 연결함
    - orders를 기준으로 user_id를 조회하고 users에 user_id랑 같은 곳에 연결함
    - 없으면 연결하지 않음

> 옆으로 붙인다고 생각하면 좋다

### 실습: 주문 상태가 완료인 행들만 확인(사용자 아이디, 이름, 주문일시)
```sql
select 
	u.user_id ,
	u.name,
	order_date
from orders o
inner join users u 
	on o.user_id = u.user_id
where o.status = 'COMPLETED';
```
- select에서 생략할 수 있는 범주
    - user_id는 orders / users 테이블 모두에 있음 => 명확히 어느 테이블의 것을 부를지 명시
    - order_date는 orders 테이블에만 있음 => 지정하지 않아도 됨
    - 실무에서는
        - 어떤 테이블의 필드인지 명시하는 것이 가독성을 높이고 좋음
        - 별칭과 함께 사용함

### 조인 작동 순서
- 논리적인 순서
    - from / join
        - 가장 먼저 from절의 orders 테입르과 innter join으로 연결된 users 테이블을 연결하기 위해 on절에 명시된 orders_user_id = users.user_id을 기준으로 가상의 테이블을 만듦
    
    - where
        - join을 통해 생성된 가상의 테이블에서 where절의 조건인 orders.status = 'COMPLETED'를 만족하는 행들만 필터링함
        - 완료된 주문 데이터만 남게됨
    
    - select

- 요약: 논리적 순서
    - from/join -> where -> select

> 쿼리 최적화: 쿼리를 더 효율적인 방식으로 실행됨(논리적 순서 / 물리적 순서 간의 차이가 있음)
- where 조건을 보고 orders 테이블에서 'COMPLETED'만 남기고 조인을 실행하면 효율적임
- 논리적 순서 / 물리적 순서의 결과는 **반드시 일치해야함**

## 내부 조인 2

### 조인과 집합
- 내부 조인: 두 테이블의 **교집합**을 찾는 것
- orders.user_id: 1 2 3 4 5
- users.user_id: 1 2 3 4 5 6
- 교집합: 1 2 3 4 5

### 집합의 관점에서 제외되는 데이터
- 주문 기록이 없는 회원
- 존재하지 않는 회원의 주문
- 결론
    - inner join은 어느 한쪽에만 데이터가 존재하는 경우는 결과에 포함시키지 않고
    - 양쪽 모두에 명확하게 연결고리가 있는 데이터만을 짝지어 보여줌  

```sql
select
	orders.order_id,
	orders.order_date,
	orders.user_id as orders_user_id,
	users.user_id as user_user_id,
	users.name
from orders
	inner join users on orders.user_id = users.user_id 
order by orders.order_id; 
```

### 내부 조인과 조인 방향
- 내부 조인은 양방향
- A -> B로 조인할 수 있다면 B -> A로 조인할 수 있음
- **그 결과는 반드시 동일함**

## 내부 조인 3

### 실무 팁: 조인 순서는 언제 중요할까/
- 주문 목록을 중심으로 고객 정보를 조회하고 싶을 때: from orders join users
- 고객 목록을 중심으로 주문 정보를 조회하고 싶을 때: from users join orders
> 결과는 반드시 같아야함
- 다만 누군가 이 쿼리를 읽을 때의 가독성이 중요!!

### 미해결 질문
- 가입은 했지만 아직 한 번도 주문하지 않은 고객은 어떻게 찾아낼 수 있을까?
- inner join으로 찾을 수 없음
- **outer join**으로 해결할 수 있음

### 가독성을 높이는 테이블 별칭
```sql
SELECT 
	u.user_id,
	u.name,
	o.order_date
FROM orders as o
INNER JOIN users as u on o.user_id = u.user_id;

SELECT 
	u.user_id,
	u.name,
	o.order_date
FROM orders o
INNER JOIN users u on o.user_id = u.user_id;
```
- 테이블 별칭 선언 시 as는 지우는 편
- 컬럼에 사용하는 별칭은 as를 반드시 써야함(가독성 및 규칙)

## 문제와 풀이

### 문제 1
```sql
select 
    o.order_id,
    p.name,
    o.quantity
from orders o
inner join products p
    on o.product_id = p.product_id
order by
	o.order_id;
```

### 문제 2
```sql
select 
    u.user_id,
    u.name,
    p.name,
    o.order_date
from orders o
    inner join users u on o.user_id = u.user_id
    inner join products p on o.product_id = p.product_id
where
    o.status = 'SHIPPED';
```

### 문제 3
```sql
select
    u.name as user_name,
    sum(p.price * o.quantity) as total_purchase_amount
from orders o
    inner join users u on o.user_id = u.user_id
    inner join products p on o.product_id = p.product_id
group by u.name
order by total_purchase_amount desc;
```
