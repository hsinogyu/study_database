# UNION

## 1. UNION

### 개념
- `JOIN`: 수평 확장 (컬럼을 옆으로 붙임)
- `UNION`: 수직 확장 (행을 아래로 붙임)

### 문제
- 현재 활동 중인 고객은 `users` 테이블에, 과거에 탈퇴한 고객은 `retired_users` 테이블에 따로 보관하고 있다. 연말을 맞아 모든 고객(활동 + 탈퇴)에게 감사 이메일을 보내려 한다. 두 테이블에 흩어진 이름과 이메일을 합쳐 하나의 전체 목록을 만들어야 한다.

### 실습 준비: `retired_users` 테이블
```sql
-- 탈퇴 고객 테이블 생성
DROP TABLE IF EXISTS retired_users;
CREATE TABLE retired_users (
    id           BIGINT PRIMARY KEY,
    name         VARCHAR(255) NOT NULL,
    email        VARCHAR(255) NOT NULL,
    retired_date DATE NOT NULL
);

-- 탈퇴 고객 데이터 입력
INSERT INTO retired_users (id, name, email, retired_date) VALUES
(1, '션', 'sean@example.com', '2024-12-31'),
(7, '아이작 뉴턴', 'newton@example.com', '2025-01-10');
```

### 사용법
```sql
select name, email from users
union
select name, email from retired_users;
```

### 핵심 규칙
- **컬럼 개수가 같아야 함**
- **같은 위치의 컬럼끼리 데이터 타입이 호환되어야 함**
- **결과의 컬럼 이름은 첫 번째 SELECT의 컬럼 이름(별칭)을 따름**
    - 두 번째 이후 SELECT의 별칭은 무시됨

### 실행 결과 해석
- 션은 두 테이블에 모두 있음
- 결과에는 션이 한 행만 나옴
- **즉, UNION은 중복된 행을 제거함**

## 2. UNION ALL

### 문제
- 마케팅 팀에서 두 그룹의 고객에게 이벤트 안내 메일을 보내려 함
    - 그룹 1: "전자기기" 카테고리 상품을 구매한 이력이 있는 고객
    - 그룹 2: "서울"에 거주하는 고객
- 생각해 볼 점
    - 서울에 살면서 전자기기를 구매한 고객은 두 그룹에 모두 속함. 이 고객을 목록에 한 번만 넣을지, 중복을 허용할지?
    - → **중복 허용 여부는 비즈니스 규칙에 따라 정함**

### UNION vs UNION ALL
| | 중복 제거 | 속도 |
|---|---|---|
| `UNION` | O | 느림 (중복 제거 작업 추가) |
| `UNION ALL` | X | 빠름 (이어 붙이면 끝) |

### 해결
```sql
-- 중복 제거 (한 사람당 한 번)
select u.name, u.email
from users u
    join orders o on u.user_id = o.user_id
    join products p on o.product_id = p.product_id
where p.category = '전자기기'

union

select u.name, u.email
from users u
where u.address like '서울%';
```

```sql
-- 중복 허용
select u.name, u.email
from users u
    join orders o on u.user_id = o.user_id
    join products p on o.product_id = p.product_id
where p.category = '전자기기'

union all

select u.name, u.email
from users u
where u.address like '서울%';
```
- 주의: UNION ALL 버전에서는 전자기기를 여러 번 산 고객이 **첫 번째 블록 안에서도** 여러 번 나옴 (join으로 주문 수만큼 행이 생기기 때문)
    - 블록 안 중복만 없애려면 첫 번째 SELECT에 `distinct`를 붙임

### 실무 가이드: 성능이 핵심
- `UNION ALL`이 `UNION`보다 빠름
    - `UNION`: 합친 뒤 중복 제거를 위한 추가 작업 필요
    - `UNION ALL`: 합치면 끝
- 가이드라인
    - 중복을 제거해야 하는 명확한 요구사항이 있을 때만 `UNION`
    - 그 외에는 `UNION ALL` 우선
        - 특히 중복이 생길 수 없다는 걸 이미 알 때 (예: 역할 컬럼에 '고객'/'직원' 같은 고정값으로 구분하는 경우)

## 3. UNION 정렬

### ORDER BY 위치
- ORDER BY는 **전체 UNION의 맨 마지막에 한 번만** 쓸 수 있음
- 맨 끝의 ORDER BY는 마지막 SELECT가 아니라 **UNION 전체 결과**에 적용됨

### 정렬 기준으로 쓸 수 있는 것
- **첫 번째 SELECT의 컬럼 이름이나 별칭**
    - 결과 집합의 컬럼 이름이 첫 번째 SELECT를 따르기 때문
- 컬럼 번호도 가능 (`order by 1 desc`). 단, 컬럼 순서가 바뀌면 깨지기 쉬움
- SELECT 결과에 없는 컬럼으로는 정렬할 수 없음

## 4. 문제와 풀이

### 전체 고객 목록 조회하기
```sql
select name as 이름, email as 이메일
from users

union

select name, email
from retired_users;
```
- 션처럼 두 테이블에 모두 있는 고객은 한 번만 나와야 하므로 `UNION`

### 특별 이벤트 대상자 목록 만들기 (중복 포함)
- 대상
    - 전자기기 카테고리 상품을 한 번이라도 구매한 고객
    - 한 번의 주문으로 상품을 2개 이상 구매한 고객
```sql
select distinct u.name as 고객명, u.email as 이메일
from users u
    inner join orders o on u.user_id = o.user_id
    inner join products p on o.product_id = p.product_id
where p.category = '전자기기'

union all

select distinct u.name, u.email
from users u
    inner join orders o on u.user_id = o.user_id
where o.quantity >= 2;
```
- `distinct`: 각 블록 안에서 중복 제거 (join으로 생긴 중복)
- `union all`: 두 조건을 모두 만족하는 고객은 두 번 나옴 (문제 조건이 "중복 포함")
- 참고: 한 사람당 한 번만 나와야 한다면 `EXISTS`로 한 번에 처리하는 게 깔끔함
```sql
select u.name as 고객명, u.email as 이메일
from users u
where exists (
    select 1
    from orders o
        inner join products p on o.product_id = p.product_id
    where o.user_id = u.user_id
      and (p.category = '전자기기' or o.quantity >= 2)
);
```

### 회사 주요 이벤트 타임라인 만들기
- '고객 가입' 이벤트와 '상품 주문' 이벤트를 시간 순서대로 정렬해서 조회
```sql
select
    u.created_at as `이벤트 날짜`,
    '고객 가입'   as `이벤트 종류`,
    u.name       as `상세 내용`
from users u

union all

select
    o.order_date,
    '상품 주문',
    p.name
from orders o
    inner join products p on o.product_id = p.product_id

order by `이벤트 날짜` desc;
```
- 별칭에 공백이 있으므로 백틱으로 감싸야 ORDER BY에서 컬럼으로 인식됨
- 날짜가 같은 행의 순서를 고정하려면 `order by \`이벤트 날짜\` desc, \`이벤트 종류\``

### 회사 전체 인명록 만들기
- 고객(users)과 직원(employees)을 통합한 인명록
```sql
select
    u.name  as `이름`,
    '고객'   as `역할`,
    u.email as `이메일`
from users u

union all

select
    e.name,
    '직원',
    concat(e.name, '@my-shop.com')
from employees e

order by `이름`;
```
- `UNION`을 쓰면 동명이인 직원이 같은 행이 되어 한 명이 사라짐 → `UNION ALL`
- 역할 값으로 두 블록이 구분되므로 애초에 겹칠 일이 없음

## 5. 새로 안 것

- DISTINCT는 행 단위로 적용됨
    - SELECT한 컬럼 값이 전부 같아야 중복으로 보고 제거함. 하나라도 다르면 남김
    - `DISTINCT(name), email`처럼 괄호를 써도 행 전체 기준인 건 같음
    - UNION으로 묶인 쿼리에서는 각 SELECT 블록 안에서만 적용됨
    - NULL끼리는 같은 값으로 봄
        - `WHERE a = NULL`은 참이 안 되지만, 중복 제거할 때는 NULL 두 개를 하나로 합침
        - 예: (홍길동, NULL)과 (홍길동, NULL)은 한 행으로 합쳐짐

- UNION의 중복 판단 기준도 DISTINCT와 같음 (행 전체, NULL끼리 같음)
    - UNION을 잘못 쓰면 동명이인 같은 진짜 데이터가 에러 없이 사라질 수 있음

- 따옴표 구분 (MySQL)
    - 백틱 `` ` ``: 식별자(테이블명, 컬럼명, 별칭). 공백·한글이 들어간 이름이나 예약어(order, user 등)에 사용
    - 작은따옴표 `'`: 문자열 값
    - 큰따옴표 `"`: MySQL에서는 문자열로 동작하지만, 표준 SQL에서는 식별자라서 다른 DB에서 에러가 남 → 문자열은 작은따옴표로 통일
    - `ORDER BY '별칭'`처럼 쓰면 문자열 상수로 취급돼서 정렬이 안 됨 (에러도 안 남)
