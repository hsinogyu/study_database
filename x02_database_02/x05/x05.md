# UNION

## UNION

### 개념
- `JOIN`: 수평 확장
- `UNION`: 수직 확장

### 문제
- 현재 활동 중인 고객을 users 테이블에, 과거에 탈퇴한 고객을 `retired_users`라는 별도의 테이블에 보과하고 있다. 연말을 마자 모든 고객(활동 + 탈퇴)에게 감사 이메일을 보내기 위해서, 두 테이블에 흩어져있는 이름과 이메일을 합쳐서 하나의 전체 목록을 만들어야 한다.

### 실습 준비: `retired_users` 테이블
```sql
-- 본 실습을 위한 탈퇴 고객 테이블 생성
DROP TABLE IF EXISTS retired_users;
CREATE TABLE retired_users (
 id BIGINT PRIMARY KEY,
 name VARCHAR(255) NOT NULL,
 email VARCHAR(255) NOT NULL,
 retired_date DATE NOT NULL
);
-- 탈퇴 고객 데이터 입력
INSERT INTO retired_users (id, name, email, retired_date) VALUES
(1, '션', 'sean@example.com', '2024-12-31'),
(7, '아이작 뉴턴', 'newton@example.com', '2025-01-10');
```

### UNION의 개념과 사용법
```sql
select name, email from users
union
select name, email from retired_users;
```

- 핵심 규칙
    - **컬럼의 개수가 동일해야 함**
    - **같은 위치에 있는 컬럼들은 서로 호환 가능한 데이터 타입**
    - **최종 결과의 컬럼 이름은 첫 번째 select 문의 컬럼 이름을 따름**

### 쿼리 실행 결과 해석
- 션은 두 테이블에 모두 있음
- 결과에는 션은 하나의 행만 존재함
- **즉, 중복된 행은 제거함**

## UNION ALL

### 문제
- 마케팅 팀에서 두 종류의 고객에게 이벤트 안내 메일을 보내려고 함
    - 첫 번쨰 그룹은 "전자기기" 카테고리의 상품을 구매한 이력이 있는 고객
    - 두 번째 그룹은 "서울"에 거주하는 고객

- 중요한 질문
    - 서울에 살면서 전자기기를 구매한 고객은 두 그룹에 모두 속하게 되는데, 이 고객을 최종 목록에 한 번만 포함해야 할까? 아니면 중복을 허용해도 될까?

- 중복 허용 여부는 비즈니스 규칙에 따라 정하는 것

### UNION과 UNION ALL의 차이
- `UNION`: 중복된 행 제거 O
- `UNION ALL`: 중복된 행 제거 X

### 해결
```sql
select u.name, u.email
from users u
	join orders o on u.user_id = o.user_id
	join products p on o.product_id = p.product_id
where p.category = '전자기기'

union

select u.name, u.email
from users u
where u.address like '서울%';

--

select u.name, u.email
from users u
	join orders o on u.user_id = o.user_id
	join products p on o.product_id = p.product_id
where p.category = '전자기기'

union all

select u.name, u.email
from users u
where u.address like '서울%';
```

### 실무 가이드: 성능이 핵심이다
- 결론: `UNION ALL`이 `UNION`보다 훨씬 빠름
- 이유:
    - `UNION`: 두 결과를 합친 뒤, 중복을 제거하기 위해 추가 작업을 진행해야함
    - `UNION ALL`: 두 결과를 합치면 끝

- 가이드라인
    - 중복을 제거해야만 하는 명확한 요구사항이 있을 때만 `UNION`을 사용
    - 그 외의 경우에는 `UNION ALL`을 우선적으로 사용
        - 특히 중복이 없다는 것을 이미 알고 있는 경우

## UNION 정렬

### 중요한 점
- order by절의 위치가 매우 중요함
- order by절은 전체 union 연산의 가장 마지막에 한 번만 사용할 수 있음

### UNION에 나오지 않는 필드를 사용한다면?
- order by 절에서는 **첫 번째 select 문의 컬럼 이름이나 해당 컬럼의 별칭만 사용할 수 있음**
- union 결과 집합의 컬럼 이름이 첫 번째 select문을 따르기 때문

## 문제와 풀이

### 전체 고객 목록 조회하기
```sql
select name as 이름, email as 이메일
from users

union

select name as 이름, email as 이메일
from retired_users;
```

### 특별 이벤트 대상자 목록 만들기 (중복 포함)
- 두 그룹의 고객에게 이벤트를 진행
    - 전자기기 카테고리 상품을 한 번이라도 구매한 고객
    - 한 번의 주문으로 상품을 2개 이상 구매한 고객
```sql
select distinct u.name as 고객명, u.email as 이메일
from users u
    inner join orders o on u.user_id = o.user_id
    inner join products p on o.product_id = p.product_id
where p.category = '전자기기'

union all

select distinct u.name, u.email
from users u
    inner join orders o on u.user_id = o.user_id
where o.quantity >= 2;
```

### 회사 주요 이벤트 타임라인 만들기
- 회사의 주요 이벤트 타임라인을 만들려고 한다. '고객 가입' 이벤트와 '상품 주문' 이벤트를 시간 순서대로 정렬하여 조회해라.
```sql
select
	u.created_at as `이벤트 날짜`,
	'고객 가입' as `이벤트 종류`,
	u.name as `상세 내용`
from users u

union all

select 
	o.order_date,
	'상품 주문',
	p.name
from orders o
	inner join products p on o.product_id = p.product_id
	
order by `이벤트 날짜` desc;
```

### 회사 전체 인명록 만들기
- 회사의 모든 관련 인물(users의 고객과 employees의 직원)을 통합한 인명록을 만들어라.
```sql
select
    u.name as `이름`,
    '고객' as `역할`,
    u.email as `이메일`
from 
    users u

union all

select 
    e.name,
    '직원',
    concat(e.name, "@my-shop.com")
from 
    employees e

order by `이름`;
```

### 새로 안 것
### 새로 안 것

- DISTINCT는 행 단위로 적용됨
    - SELECT한 컬럼 값이 전부 같아야 중복으로 보고 제거함. 하나라도 다르면 남김
    - `DISTINCT(name), email`처럼 괄호를 써도 행 전체 기준인 건 같음
    - UNION으로 묶인 쿼리에서는 각 SELECT 블록 안에서만 적용됨
    - NULL끼리는 같은 값으로 봄
        - `WHERE a = NULL`은 참이 안 되지만, 중복 제거할 때는 NULL 두 개를 하나로 합침
        - 예: (홍길동, NULL)과 (홍길동, NULL)은 한 행으로 합쳐짐

- UNION의 중복 판단 기준도 DISTINCT와 같음 (행 전체, NULL끼리 같음)
    - UNION: 합친 결과 전체에서 중복 제거
    - UNION ALL: 중복 제거 없이 그대로 이어 붙임 (더 빠름)
    - 겹칠 수 없는 집합을 합칠 때는 UNION ALL
        - 예: 역할 컬럼에 '고객'/'직원'처럼 고정값을 넣어 구분할 때
    - UNION을 잘못 쓰면 동명이인 같은 진짜 데이터가 에러 없이 사라질 수 있음

- UNION 결과 다루기
    - 컬럼명은 첫 번째 SELECT의 별칭을 따름
    - 맨 끝의 ORDER BY는 UNION 전체 결과에 적용됨

- 따옴표 구분 (MySQL)
    - 백틱 `` ` ``: 식별자(테이블명, 컬럼명, 별칭). 공백·한글이 들어간 이름이나 예약어(order, user 등)에 사용
    - 작은따옴표 `'`: 문자열 값
    - `ORDER BY '별칭'`처럼 쓰면 문자열 상수로 취급돼서 정렬이 안 됨 (에러도 안 남)
