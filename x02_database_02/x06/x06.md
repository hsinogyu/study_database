# CASE

## CASE 문 기본 1

### 개념
- CASE문은 데이터 자체를 동적으로 가공하고 새로운 의미를 부여하는, 데이터에 멋진 옷을 입히는 기술
- 마치 IF-THEN-ELSE처럼, 특정 조건에 따라 다른 값을 출력하게 만드는 SQL의 강력한 조건부 로직 도구

### 문제
- 상품 목록을 조회하는데, 그냥 가격만 보여주지 말고, 가격대에 따라 `고가`, `중가`, `저가`와 같은 알아보기 쉬운 등급을 앞에 함게 표시하고 싶음
    - 10만원 이상: 고가
    - 3만원 이상 10만원 미만: 중가
    - 3만원 미만: 저가

### CASE 문의 두 가지 종류
- 단순 CASE문
- 검색 CASE문

### 단순 CASE문 (Simple CASE Expression)
- 특정 하나의 컬럼이나 표현식의 값에 따라 결과를 다르게 하고 싶을 때 사용함
- 특정 값을 기준으로 이 값이 A면 X, B면 Y, 그 외에는 Z와 같이 명확하게 분기할 때 유용함

### 단순 CASE문의 기본 문법
```sql
CASE 비교대상_컬럼_또는_표현식
    WHEN 값1 THEN 결과1
    WHEN 값2 THEN 결과2
    ...
    ELSE 그_외의_경우_결과
END
```
- ELSE를 생략했는데 모든 WHEN 조건이 거짓이면 NULL이 반환됨

### 단순 CASE 문 예제: 주문 상태(status)를 한글로 표시하기
```sql
select
    order_id,
    user_id,
    product_id,
    quantity,
    status,
    case status
        when 'PENDING' THEN '주문 대기'
        when 'COMPLETED' THEN '결제 완료'
        when 'SHIPPED' THEN '배송'
        when 'CANCELLED' THEN '주문 취소'
        else '알 수 없음'
    end as status_korean
from orders;
```

### 검색 CASE문(Searched CASE Expression)
- when 절에 독립적인 조건식을 사용하여 복잡한 논리를 구현할 때 사용함

### 검색 CASE 문의 기본 문법
```sql
CASE
 WHEN 조건1 THEN 결과1
 WHEN 조건2 THEN 결과2
 ...
 ELSE 그_외의_경우_결과
END
```
- ELSE를 생략했는데 모든 WHEN 조건이 거짓이면 NULL이 반환됨

### 검색 CASE 문 예제: 상품 가격에 따라 등급 표시하기
```sql
select
    name,
    price,
    case
        when price >= 100000 then '고가'
        when price >= 30000 then '중가'
        else '저가'
    end as price_label
from
    products;
```

## CASE문 기본 2

### 검색 CASE 문 사용 시 주의사항: WEHEN 절의 순서
- **가장 먼저 참이 되는 조건을 만나는 순간 실앻을 멈춤**
- 범위가 좁은 조건을 먼저 배치는 것이 좋음

### CASE 문과 사용 위치
- select
- order by
- group by
- where
```sql
select
    name,
    price,
    case
        when price >= 100000 then '고가'
        when price >= 30000 then '중가'
        else '저가'
    end as price_label
from
    products
order by
    case 
        when price >= 100000 then 1
        when price >= 30000 then 2
        else 3
    end asc,
    price desc;
```
- 각 행에 저 숫자를 달아놓고 정렬을 수행함

## CASE문 - 그룹핑

### 문제
- 고객들의 출생 연대에 따라 1990년대, 1980년대, 그 이전 출생으로 분류
- 각 그룹에 고객이 총 몇 명이 있는지 알고 싶음

- 해결
    - 분류: CASE문을 사용해서 각 고객에게 라벨을 붙여줌
    - 집계: 라벨을 기준으로 GROUP BY문을 사용해서 COUNT() 함수를 사용해 각 라벨에 속한 고객 수를 셈

### 분류
```sql
select
    u.name,
    u.birth_date
    case 
        when year(birth_date) >= 1990 then '1990년대생'
        when year(birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end as birth_decade
from users u;
```

### 집계
```sql
select
    count(*) as customer_count,
    case 
        when year(birth_date) >= 1990 then '1990년대생'
        when year(birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end as birth_decade
from users u
group by 
    case 
        when year(birth_date) >= 1990 then '1990년대생'
        when year(birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end;
```

### select절의 컬럼으로 group by하기
```sql
select
    count(*) as customer_count,
    case 
        when year(birth_date) >= 1990 then '1990년대생'
        when year(birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end as birth_decade
from users u
group by birth_decade
```
- 논리적으로 안됨
    - from -> where -> group by -> having -> select -> order by
    - 따라서 select에서 사용한 별칭(컬럼)으로 그룹핑은 원칙적으로 할 수 없음

- 데이터베이스의 지원
    - MySQL을 포함한 많은 데이터베이스들은 사용자 편의를 위해 이러한 별칭 사용을 예외적으로 허용함

## CASE문 - 조건부 집계 1

### 조건부 집계
- CASE문이 집계 함수 안으로 들어가는 것

### 문제
> 하나의 쿼리로, 전체 주문 건수와 함께 결제 완료, 배송, 주문 대기, 상태의 주문이 각각 몇 건인지 별도의 컬럼으로 나누어 보고 싶다.

- 피벗 테이블
    - 데이터를 다양한 관점에서 회전(pivot) 시켜 분석할 수 있는 기능 때문에 붙여진 이름

### 해결
- UNION으로 합치는 방법
```sql
select 
    'Total' as category,
    count(*) as total_orders
from 
    orders

union all

select
    status,
    count(*)
from
    orders
group by status;
```
    - 피벗 테이블의 형태는 아님

- 서브 쿼리를 사용하는 방법
```sql
select
	(select count(*) from orders) as total_orders,
	(select count(*) from orders where status = 'completed') as completed_count,
	(select count(*) from orders where status = 'shiped') as shiped_count,
	(select count(*) from orders where status = 'pending') as pending_count	
```
    - 원하는 목적은 이룸
    - 심각한 성능 문제
        - orders 테이블을 4번이나 읽음

### 근복적인 해결
- CASE문을 집계함수에 넣음으로써 해결할 수 있음

## CASE문 - 조건부 집계 2

### CASE문을 품은 집계 함수
- 집계 함수의 인자로 CASE문을 넣어 조건에 맞을 때만 세거나 더하게 만드는 방식

### 패턴 1: COUNT(CASE ...)
```sql
count(case when status = 'completed' then 1 end)
```
- count 함수는 null이 아닌 모든 값을 샌다는 특징이 있음
    - status가 'completed'이면 case문은 숫자 1을 반환함
    - 그 외의 경우(else가 없으므로), case문은 null을 반환함
    - 결과적으로 count함수는 status가 'completed'인 행의 개수만 세게 됨

### 패턴 2: SUM(CASE ...)
```sql
sum(case when status = 'completed' then 1 else 0 end)
```
- sum 함수는 숫자들의 합계를 구함
    - status가 'completed'이면 case문은 1을, 그 외에는 0을 반환
    - sum 함수가 이 1과 0들을 모두 더하면, 그 합계는 결국 'completed' 상태인 주문의 총 개수가 됨

### 해결
```sql
select
    count(*) as total_orders,
    sum(case when status = 'completed' then 1 else 0 end) as completed_total,
    sum(case when status = 'shipped' then 1 else 0 end) as shipped_total,
    sum(case when status = 'pending' then 1 else 0 end) as pending_total
from orders;
```
- orders를 한 번만 조회해서 빠르게 처리함


### 실습 2: group by와 함께 사용하기 (피벗 테이블)
- 추가 요구사항
    - 상품 카테고리별로, 상태별 주문 건수를 집계하라

```sql
select 
	p.category,
    count(*) as total_orders,
    sum(case when status = 'completed' then 1 else 0 end) as completed_total,
    sum(case when status = 'shipped' then 1 else 0 end) as shipped_total,
    sum(case when status = 'pending' then 1 else 0 end) as pending_total
from orders o
inner join products p on o.product_id = p.product_id
group by p.category;
```
