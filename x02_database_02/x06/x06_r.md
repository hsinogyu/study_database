# CASE

## 1. CASE 문 기본

### 개념
- 조건에 따라 다른 값을 출력하는 SQL의 조건부 로직 (프로그래밍 언어의 IF-THEN-ELSE와 비슷함)
- 데이터를 그대로 보여주지 않고, 가공해서 새로운 의미(라벨, 등급 등)를 붙일 때 사용

### 문제
- 상품 목록을 조회할 때, 가격만 보여주지 말고 가격대에 따라 `고가`, `중가`, `저가` 등급을 함께 표시하고 싶음
    - 10만원 이상: 고가
    - 3만원 이상 10만원 미만: 중가
    - 3만원 미만: 저가

### CASE 문의 두 가지 종류
| 종류 | 언제 쓰나 | 형태 |
|---|---|---|
| 단순 CASE | 하나의 컬럼 값이 무엇인지에 따라 분기 (`=` 비교만 가능) | `CASE 컬럼 WHEN 값 THEN ...` |
| 검색 CASE | WHEN마다 자유로운 조건식 (범위, AND/OR 등) | `CASE WHEN 조건 THEN ...` |

---

### 단순 CASE (Simple CASE Expression)
- 특정 컬럼(또는 표현식)의 값이 A면 X, B면 Y, 그 외에는 Z처럼 값으로 딱 나눌 때 유용

```sql
CASE 비교대상_컬럼_또는_표현식
    WHEN 값1 THEN 결과1
    WHEN 값2 THEN 결과2
    ...
    ELSE 그_외의_경우_결과
END
```

#### 예제: 주문 상태(status)를 한글로 표시하기
```sql
select
    order_id,
    user_id,
    product_id,
    quantity,
    status,
    case status
        when 'PENDING'   then '주문 대기'
        when 'COMPLETED' then '결제 완료'
        when 'SHIPPED'   then '배송'
        when 'CANCELLED' then '주문 취소'
        else '알 수 없음'
    end as status_korean
from orders;
```

#### 주의: 단순 CASE로는 NULL을 잡을 수 없음
- 단순 CASE는 내부적으로 `status = 값`으로 비교함
- `when null then ...`은 `status = null`이 되어 절대 참이 안 됨 → ELSE로 빠짐
- NULL을 따로 처리하려면 검색 CASE에서 `when status is null then ...`을 사용

---

### 검색 CASE (Searched CASE Expression)
- WHEN 절마다 독립적인 조건식을 써서 복잡한 논리를 구현할 때 사용

```sql
CASE
    WHEN 조건1 THEN 결과1
    WHEN 조건2 THEN 결과2
    ...
    ELSE 그_외의_경우_결과
END
```

#### 예제: 상품 가격에 따라 등급 표시하기
```sql
select
    name,
    price,
    case
        when price >= 100000 then '고가'
        when price >= 30000  then '중가'
        else '저가'
    end as price_label
from products;
```

### 공통 규칙
- ELSE를 생략했는데 모든 WHEN이 거짓이면 **NULL**이 반환됨
- `END`로 반드시 닫아야 함
- 결과값들의 데이터 타입은 맞추는 게 좋음 (문자와 숫자를 섞지 않기)

## 2. CASE 문 주의사항과 사용 위치

### WHEN 절의 순서가 중요함
- 위에서부터 차례로 검사하고, **처음으로 참이 되는 WHEN을 만나면 거기서 멈춤** (아래 WHEN은 검사하지 않음)
- 그래서 **더 좁은(엄격한) 조건을 먼저** 배치해야 함

```sql
-- 잘못된 순서: 10만원 이상도 price >= 30000에 먼저 걸려서 전부 '중가'가 됨
case
    when price >= 30000  then '중가'
    when price >= 100000 then '고가'   -- 절대 도달하지 않음
    else '저가'
end
```
- 순서를 이용하면 조건을 짧게 쓸 수 있음
    - 두 번째 WHEN에 `price >= 30000 and price < 100000`이라고 쓸 필요 없음 (10만원 이상은 이미 첫 번째에서 걸러짐)

### CASE를 쓸 수 있는 위치
- SELECT, ORDER BY, GROUP BY, WHERE 등 **값이 들어갈 수 있는 곳이면 어디든**

#### ORDER BY에서 사용: 원하는 순서로 정렬하기
```sql
select
    name,
    price,
    case
        when price >= 100000 then '고가'
        when price >= 30000  then '중가'
        else '저가'
    end as price_label
from products
order by
    case
        when price >= 100000 then 1
        when price >= 30000  then 2
        else 3
    end asc,
    price desc;
```
- 각 행에 1, 2, 3 숫자를 붙여서 그 숫자로 정렬 → 고가 → 중가 → 저가 순
- 같은 등급 안에서는 가격 내림차순
- 문자열 라벨(`price_label`)로 정렬하면 가나다순이 되어 원하는 순서가 안 나옴. 그래서 숫자로 정렬함

#### WHERE에서 사용 (예시)
```sql
-- 등급이 '중가'인 상품만 조회
select name, price
from products
where case
          when price >= 100000 then '고가'
          when price >= 30000  then '중가'
          else '저가'
      end = '중가';
```
- 실무에서는 `where price >= 30000 and price < 100000`처럼 조건을 직접 쓰는 게 더 읽기 쉽고 인덱스도 탈 수 있음

## 3. CASE + GROUP BY: 그룹핑

### 문제
- 고객을 출생 연대에 따라 1990년대, 1980년대, 그 이전 출생으로 분류하고
- 각 그룹의 고객 수를 알고 싶음

### 해결 흐름
1. **분류:** CASE로 각 고객에게 라벨을 붙임
2. **집계:** 그 라벨을 기준으로 GROUP BY 하고 COUNT()로 고객 수를 셈

### 1단계: 분류
```sql
select
    u.name,
    u.birth_date,
    case
        when year(u.birth_date) >= 1990 then '1990년대생'
        when year(u.birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end as birth_decade
from users u;
```

### 2단계: 집계
```sql
select
    case
        when year(birth_date) >= 1990 then '1990년대생'
        when year(birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end as birth_decade,
    count(*) as customer_count
from users
group by
    case
        when year(birth_date) >= 1990 then '1990년대생'
        when year(birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end;
```
- 표준 SQL에서는 GROUP BY에 CASE 식 전체를 똑같이 다시 써야 함

### SELECT의 별칭으로 GROUP BY 하기
```sql
select
    case
        when year(birth_date) >= 1990 then '1990년대생'
        when year(birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end as birth_decade,
    count(*) as customer_count
from users
group by birth_decade;
```
- **원칙적으로는 안 됨**
    - SQL의 논리적 실행 순서: `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`
    - GROUP BY가 SELECT보다 먼저 실행되므로, SELECT에서 만든 별칭을 GROUP BY에서는 아직 모름
- **하지만 MySQL은 허용함**
    - MySQL을 포함한 여러 DB가 편의를 위해 예외적으로 허용
    - 다른 DB(Oracle 등)에서는 에러가 날 수 있으므로 이식성이 필요하면 식 전체를 다시 쓰기
- 참고: ORDER BY는 SELECT 다음에 실행되므로 **별칭 사용이 표준에서도 가능**

### 주의: NULL은 ELSE로 빠짐
- `birth_date`가 NULL이면 `year(NULL)`도 NULL → 모든 WHEN이 거짓 → `'그 이전 출생'`으로 분류됨
- 생년월일이 없는 고객이 엉뚱한 그룹에 섞이지 않게 하려면 NULL을 먼저 따로 처리
```sql
case
    when birth_date is null          then '정보 없음'
    when year(birth_date) >= 1990    then '1990년대생'
    when year(birth_date) >= 1980    then '1980년대생'
    else '그 이전 출생'
end
```
- 라벨도 확인할 것: `>= 1990` 조건에는 2000년대생도 포함됨 → 정확히는 `'1990년 이후 출생'`

## 새로 안 것

- CASE는 위에서부터 검사하고 처음 참인 WHEN에서 멈춤 → 좁은 조건을 먼저
- ELSE를 생략하면 해당 없는 행은 NULL
- 단순 CASE는 `=` 비교라서 NULL을 잡지 못함 → `is null`은 검색 CASE로
- NULL 값은 모든 WHEN을 통과해서 ELSE로 빠짐 → 의도치 않은 분류 주의
- ORDER BY에 CASE로 숫자를 매기면 원하는 순서대로 정렬 가능
- SQL 논리적 실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
    - GROUP BY에서 SELECT 별칭 사용: 원칙적으로 불가, MySQL은 허용
    - ORDER BY에서 SELECT 별칭 사용: 표준에서도 가능
