# CASE

## 1. CASE 문 기본

### 개념
- 조건에 따라 다른 값을 출력하는 SQL의 조건부 로직 (프로그래밍 언어의 IF-THEN-ELSE와 비슷함)
- 데이터를 그대로 보여주지 않고, 가공해서 새로운 의미(라벨, 등급 등)를 붙일 때 사용

### 문제
- 상품 목록을 조회할 때, 가격만 보여주지 말고 가격대에 따라 `고가`, `중가`, `저가` 등급을 함께 표시하고 싶음
    - 10만원 이상: 고가
    - 3만원 이상 10만원 미만: 중가
    - 3만원 미만: 저가

### CASE 문의 두 가지 종류
| 종류 | 언제 쓰나 | 형태 |
|---|---|---|
| 단순 CASE | 하나의 컬럼 값이 무엇인지에 따라 분기 (`=` 비교만 가능) | `CASE 컬럼 WHEN 값 THEN ...` |
| 검색 CASE | WHEN마다 자유로운 조건식 (범위, AND/OR 등) | `CASE WHEN 조건 THEN ...` |

---

### 단순 CASE (Simple CASE Expression)
- 특정 컬럼(또는 표현식)의 값이 A면 X, B면 Y, 그 외에는 Z처럼 값으로 딱 나눌 때 유용

```sql
CASE 비교대상_컬럼_또는_표현식
    WHEN 값1 THEN 결과1
    WHEN 값2 THEN 결과2
    ...
    ELSE 그_외의_경우_결과
END
```

#### 예제: 주문 상태(status)를 한글로 표시하기
```sql
select
    order_id,
    user_id,
    product_id,
    quantity,
    status,
    case status
        when 'PENDING'   then '주문 대기'
        when 'COMPLETED' then '결제 완료'
        when 'SHIPPED'   then '배송'
        when 'CANCELLED' then '주문 취소'
        else '알 수 없음'
    end as status_korean
from orders;
```

#### 주의: 단순 CASE로는 NULL을 잡을 수 없음
- 단순 CASE는 내부적으로 `status = 값`으로 비교함
- `when null then ...`은 `status = null`이 되어 절대 참이 안 됨 → ELSE로 빠짐
- NULL을 따로 처리하려면 검색 CASE에서 `when status is null then ...`을 사용

---

### 검색 CASE (Searched CASE Expression)
- WHEN 절마다 독립적인 조건식을 써서 복잡한 논리를 구현할 때 사용

```sql
CASE
    WHEN 조건1 THEN 결과1
    WHEN 조건2 THEN 결과2
    ...
    ELSE 그_외의_경우_결과
END
```

#### 예제: 상품 가격에 따라 등급 표시하기
```sql
select
    name,
    price,
    case
        when price >= 100000 then '고가'
        when price >= 30000  then '중가'
        else '저가'
    end as price_label
from products;
```

### 공통 규칙
- ELSE를 생략했는데 모든 WHEN이 거짓이면 **NULL**이 반환됨
- `END`로 반드시 닫아야 함
- 결과값들의 데이터 타입은 맞추는 게 좋음 (문자와 숫자를 섞지 않기)

## 2. CASE 문 주의사항과 사용 위치

### WHEN 절의 순서가 중요함
- 위에서부터 차례로 검사하고, **처음으로 참이 되는 WHEN을 만나면 거기서 멈춤** (아래 WHEN은 검사하지 않음)
- 그래서 **더 좁은(엄격한) 조건을 먼저** 배치해야 함

```sql
-- 잘못된 순서: 10만원 이상도 price >= 30000에 먼저 걸려서 전부 '중가'가 됨
case
    when price >= 30000  then '중가'
    when price >= 100000 then '고가'   -- 절대 도달하지 않음
    else '저가'
end
```
- 순서를 이용하면 조건을 짧게 쓸 수 있음
    - 두 번째 WHEN에 `price >= 30000 and price < 100000`이라고 쓸 필요 없음 (10만원 이상은 이미 첫 번째에서 걸러짐)

### CASE를 쓸 수 있는 위치
- SELECT, ORDER BY, GROUP BY, WHERE 등 **값이 들어갈 수 있는 곳이면 어디든**

#### ORDER BY에서 사용: 원하는 순서로 정렬하기
```sql
select
    name,
    price,
    case
        when price >= 100000 then '고가'
        when price >= 30000  then '중가'
        else '저가'
    end as price_label
from products
order by
    case
        when price >= 100000 then 1
        when price >= 30000  then 2
        else 3
    end asc,
    price desc;
```
- 각 행에 1, 2, 3 숫자를 붙여서 그 숫자로 정렬 → 고가 → 중가 → 저가 순
- 같은 등급 안에서는 가격 내림차순
- 문자열 라벨(`price_label`)로 정렬하면 가나다순이 되어 원하는 순서가 안 나옴. 그래서 숫자로 정렬함

#### WHERE에서 사용 (예시)
```sql
-- 등급이 '중가'인 상품만 조회
select name, price
from products
where case
          when price >= 100000 then '고가'
          when price >= 30000  then '중가'
          else '저가'
      end = '중가';
```
- 실무에서는 `where price >= 30000 and price < 100000`처럼 조건을 직접 쓰는 게 더 읽기 쉽고 인덱스도 탈 수 있음

## 3. CASE + GROUP BY: 그룹핑

### 문제
- 고객을 출생 연대에 따라 1990년대, 1980년대, 그 이전 출생으로 분류하고
- 각 그룹의 고객 수를 알고 싶음

### 해결 흐름
1. **분류:** CASE로 각 고객에게 라벨을 붙임
2. **집계:** 그 라벨을 기준으로 GROUP BY 하고 COUNT()로 고객 수를 셈

### 1단계: 분류
```sql
select
    u.name,
    u.birth_date,
    case
        when year(u.birth_date) >= 1990 then '1990년대생'
        when year(u.birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end as birth_decade
from users u;
```

### 2단계: 집계
```sql
select
    case
        when year(birth_date) >= 1990 then '1990년대생'
        when year(birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end as birth_decade,
    count(*) as customer_count
from users
group by
    case
        when year(birth_date) >= 1990 then '1990년대생'
        when year(birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end;
```
- 표준 SQL에서는 GROUP BY에 CASE 식 전체를 똑같이 다시 써야 함

### SELECT의 별칭으로 GROUP BY 하기
```sql
select
    case
        when year(birth_date) >= 1990 then '1990년대생'
        when year(birth_date) >= 1980 then '1980년대생'
        else '그 이전 출생'
    end as birth_decade,
    count(*) as customer_count
from users
group by birth_decade;
```
- **원칙적으로는 안 됨**
    - SQL의 논리적 실행 순서: `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`
    - GROUP BY가 SELECT보다 먼저 실행되므로, SELECT에서 만든 별칭을 GROUP BY에서는 아직 모름
- **하지만 MySQL은 허용함**
    - MySQL을 포함한 여러 DB가 편의를 위해 예외적으로 허용
    - 다른 DB(Oracle 등)에서는 에러가 날 수 있으므로 이식성이 필요하면 식 전체를 다시 쓰기
- 참고: ORDER BY는 SELECT 다음에 실행되므로 **별칭 사용이 표준에서도 가능**

### 주의: NULL은 ELSE로 빠짐
- `birth_date`가 NULL이면 `year(NULL)`도 NULL → 모든 WHEN이 거짓 → `'그 이전 출생'`으로 분류됨
- 생년월일이 없는 고객이 엉뚱한 그룹에 섞이지 않게 하려면 NULL을 먼저 따로 처리
```sql
case
    when birth_date is null          then '정보 없음'
    when year(birth_date) >= 1990    then '1990년대생'
    when year(birth_date) >= 1980    then '1980년대생'
    else '그 이전 출생'
end
```
- 라벨도 확인할 것: `>= 1990` 조건에는 2000년대생도 포함됨 → 정확히는 `'1990년 이후 출생'`

## 4. CASE + 집계 함수: 조건부 집계

### 개념
- CASE를 **집계 함수(COUNT, SUM 등) 안에** 넣어서, 조건에 맞는 행만 세거나 더하는 방식
- 행으로 나뉘어 있는 데이터를 **컬럼으로 펼쳐서** 보여줄 수 있음 → 피벗 테이블
    - 피벗(pivot): 데이터를 회전시켜 다른 관점으로 본다는 뜻

### 문제
> 하나의 쿼리로 전체 주문 건수와 함께, 결제 완료 / 배송 / 주문 대기 상태의 주문이 각각 몇 건인지 별도의 컬럼으로 나누어 보고 싶다.

원하는 결과 형태:

| total_orders | completed_total | shipped_total | pending_total |
|---|---|---|---|
| 20 | 8 | 5 | 4 |

### 시도 1: UNION으로 합치기
```sql
select
    'Total'  as category,
    count(*) as order_count
from orders

union all

select
    status,
    count(*)
from orders
group by status;
```
- 숫자는 다 나오지만 **행으로 나열**됨 → 원하는 피벗 형태(컬럼으로 펼친 형태)가 아님

### 시도 2: 스칼라 서브쿼리 여러 개
```sql
select
    (select count(*) from orders)                           as total_orders,
    (select count(*) from orders where status = 'COMPLETED') as completed_count,
    (select count(*) from orders where status = 'SHIPPED')   as shipped_count,
    (select count(*) from orders where status = 'PENDING')   as pending_count;
```
- 원하는 형태는 나옴
- 하지만 **orders 테이블을 4번 읽음** → 컬럼이 늘어날수록, 데이터가 많을수록 느려짐

### 근본적인 해결: 집계 함수 안에 CASE
- 테이블을 **한 번만 읽으면서** 각 행마다 "이 행이 어느 컬럼에 해당하나"를 CASE로 판단

---

### 패턴 1: COUNT(CASE ...)
```sql
count(case when status = 'COMPLETED' then 1 end)
```
- COUNT(컬럼)은 **NULL이 아닌 값만 셈**
    - 조건에 맞으면 CASE가 1을 반환 → 셈
    - 맞지 않으면 ELSE가 없으니 NULL 반환 → 세지 않음
- 결과적으로 조건에 맞는 행의 개수만 셈
- THEN 값은 1이 아니어도 됨 (NULL만 아니면 됨). 관례상 1을 씀

#### 자주 하는 실수: COUNT에 else 0
```sql
count(case when status = 'COMPLETED' then 1 else 0 end)   -- 잘못됨
```
- 0도 NULL이 아닌 값이라서 **모든 행을 셈** → `count(*)`와 같은 결과가 나옴
- COUNT에는 ELSE를 쓰지 않거나 `else null`

### 패턴 2: SUM(CASE ...)
```sql
sum(case when status = 'COMPLETED' then 1 else 0 end)
```
- 조건에 맞으면 1, 아니면 0을 반환 → 다 더하면 조건에 맞는 행의 개수
- SUM은 `else 0`을 붙이는 게 좋음
    - ELSE가 없어도 SUM은 NULL을 무시하므로 결과는 같음
    - 단, 조건에 맞는 행이 **하나도 없으면** `else 0` 없이는 결과가 0이 아니라 **NULL**이 됨

### COUNT vs SUM 정리
| | 쓰는 법 | ELSE |
|---|---|---|
| COUNT | `count(case when 조건 then 1 end)` | 쓰지 않음 (0을 넣으면 전부 셈) |
| SUM | `sum(case when 조건 then 1 else 0 end)` | `else 0` (해당 행이 없을 때 NULL 방지) |
- SUM 방식은 1 대신 금액을 넣으면 **조건부 합계**도 구할 수 있음
    - 예: `sum(case when status = 'COMPLETED' then o.quantity * p.price else 0 end)` → 결제 완료된 매출 합계

---

### 해결
```sql
select
    count(*) as total_orders,
    sum(case when status = 'COMPLETED' then 1 else 0 end) as completed_total,
    sum(case when status = 'SHIPPED'   then 1 else 0 end) as shipped_total,
    sum(case when status = 'PENDING'   then 1 else 0 end) as pending_total
from orders;
```
- orders를 **한 번만** 읽어서 처리

### 실습: GROUP BY와 함께 쓰기 (피벗 테이블)
- 추가 요구사항: 상품 카테고리별로, 상태별 주문 건수를 집계하라

```sql
select
    p.category,
    count(*) as total_orders,
    sum(case when o.status = 'COMPLETED' then 1 else 0 end) as completed_total,
    sum(case when o.status = 'SHIPPED'   then 1 else 0 end) as shipped_total,
    sum(case when o.status = 'PENDING'   then 1 else 0 end) as pending_total
from orders o
    inner join products p on o.product_id = p.product_id
group by p.category;
```
- GROUP BY가 행을 카테고리별로 나누고, 그 안에서 CASE가 상태별로 컬럼을 나눔
    - 행 방향: 카테고리
    - 열 방향: 주문 상태
- join을 쓸 때는 `o.status`처럼 테이블 별칭을 붙이는 게 안전함 (같은 이름의 컬럼이 생기면 모호해짐)

### 참고: 상태값 문자열 주의
- 상태값 철자가 틀리면(`'shiped'`) 에러 없이 **0건**으로 나옴 → 결과가 이상하면 철자부터 확인
- 대소문자: MySQL의 기본 설정(collation)은 대소문자를 구분하지 않아 `'completed'`와 `'COMPLETED'`가 같게 비교됨
    - 하지만 다른 DB나 설정에서는 구분하므로, 실제 저장된 값(`'COMPLETED'`)과 똑같이 쓰는 습관을 들이기

## 5. 새로 안 것

- CASE는 위에서부터 검사하고 처음 참인 WHEN에서 멈춤 → 좁은 조건을 먼저
- ELSE를 생략하면 해당 없는 행은 NULL
- 단순 CASE는 `=` 비교라서 NULL을 잡지 못함 → `is null`은 검색 CASE로
- NULL 값은 모든 WHEN을 통과해서 ELSE로 빠짐 → 의도치 않은 분류 주의
- ORDER BY에 CASE로 숫자를 매기면 원하는 순서대로 정렬 가능
- SQL 논리적 실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
    - GROUP BY에서 SELECT 별칭 사용: 원칙적으로 불가, MySQL은 허용
    - ORDER BY에서 SELECT 별칭 사용: 표준에서도 가능
- 조건부 집계: 집계 함수 안에 CASE를 넣으면 테이블을 한 번만 읽고 여러 조건을 동시에 집계할 수 있음
    - 서브쿼리를 여러 개 쓰면 테이블을 그 횟수만큼 읽음 → 느림
    - `count(case ... then 1 end)`: ELSE 없이. `else 0`을 넣으면 전부 세어버림
    - `sum(case ... then 1 else 0 end)`: `else 0`으로 결과 NULL 방지
    - GROUP BY와 함께 쓰면 피벗 테이블 (행: 그룹 기준, 열: CASE 조건)
- 조건의 문자열 값이 틀리면 에러 없이 0건이 나옴 → 결과가 이상하면 값부터 확인
